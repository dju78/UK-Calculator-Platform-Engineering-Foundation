## Purpose

Convert a run into pace, speed and predicted race times.

## Scope

A distance and a time.

## Assumptions

- Race predictions extrapolate the current pace unchanged.

## Inputs

| Name | Label | Type | Default | Units / notes |
|---|---|---|---|---|
| `distance_km` | Distance (km) | number | 5 | - |
| `hours` | Hours | number | 0 | - |
| `minutes` | Minutes | number | 25 | - |
| `seconds` | Seconds | number | 0 | - |

Percentages are entered as human percentages (5 means 5%) and normalised once
inside the engine.

## Validation

Enforced centrally at the engine boundary and by the shared validation module:

- Any non-finite input is rejected with a readable message.
- Any non-finite output is rejected rather than returned, so `NaN` and
  `Infinity` can never reach a user.
- Terms are bounded (maximum 150 years) and monetary amounts capped, so no
  input can spin an amortisation loop indefinitely.
- A time of zero is refused.

## Formula and logic

Pace is total seconds over distance; speed is distance over hours. Race predictions multiply the pace by the standard distances.

## Outputs

- `pace_per_km`
- `pace_per_mile`
- `speed_kmh`
- `speed_mph`
- `finish_time_5k`
- `finish_time_10k`
- `finish_time_half_marathon`
- `finish_time_marathon`

Formatting is decided by the central registry in
`apps/web/src/components/calculators/outputFormats.ts`, per calculator and per
key, so ratios render as percentages and money as `£1,234.56`.

## Rules and source dependencies

Not rules-sensitive. No statutory values are used.

## Product boundary

The predictions are OPTIMISTIC: almost everyone slows as the distance grows, and the marathon figure in particular should be read as a ceiling rather than a target.

## Methodology

The oracle verifies that the pace multiplied back by the distance returns the original time exactly, and a test checks that the 10 km prediction for a 10 km run equals the time actually run.
