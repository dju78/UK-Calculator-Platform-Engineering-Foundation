## Purpose

Add or subtract hours, minutes and seconds from a time of day.

## Scope

A start time and a period, in either direction.

## Assumptions

- A 24-hour clock with no daylight saving transition inside the calculation.

## Inputs

| Name | Label | Type | Default | Units / notes |
|---|---|---|---|---|
| `start_time` | Start time | text | "09:30" | In 24-hour form, for example 14:30. |
| `operation` | Add or subtract? | select | "add" | - |
| `hours` | Hours | number | 3 | - |
| `minutes` | Minutes | number | 15 | - |
| `seconds` | Seconds | number | 0 | - |

Percentages are entered as human percentages (5 means 5%) and normalised once
inside the engine.

## Validation

Enforced centrally at the engine boundary and by the shared validation module:

- Any non-finite input is rejected with a readable message.
- Any non-finite output is rejected rather than returned, so `NaN` and
  `Infinity` can never reach a user.
- Terms are bounded (maximum 150 years) and monetary amounts capped, so no
  input can spin an amortisation loop indefinitely.
- Times are accepted as HH:MM or HH:MM:SS on a 24-hour clock. Anything else is refused with the expected format shown, because "5.30" is ambiguous between half past five and five hours thirty of something.

## Formula and logic

The whole calculation is done in seconds, then reduced modulo a day, with the number of whole days carried reported separately.

## Outputs

- `result_time`
- `days_carried`
- `total_seconds`

Formatting is decided by the central registry in
`apps/web/src/components/calculators/outputFormats.ts`, per calculator and per
key, so ratios render as percentages and money as `£1,234.56`.

## Edge cases covered by benchmarks

- **Add hours within the day** - {"start_time":"09:30","hours":3,"minutes":15,"seconds":0,"operation":"add"}
- **Add hours across midnight** - {"start_time":"22:45","hours":4,"minutes":30,"seconds":0,"operation":"add"}
- **Subtract across midnight** - {"start_time":"01:15","hours":3,"minutes":0,"seconds":0,"operation":"subtract"}
- **Add exactly a day** - {"start_time":"12:00","hours":24,"minutes":0,"seconds":0,"operation":"add"}
- **Add with seconds** - {"start_time":"08:00:00","hours":0,"minutes":90,"seconds":45,"operation":"add"}
- **Subtract within the day** - {"start_time":"17:00","hours":8,"minutes":30,"seconds":0,"operation":"subtract"}

## Product boundary

THE DAYS CARRIED FIGURE IS AN OUTPUT, NOT A DETAIL. Adding nine hours to 20:00 gives 05:00 the following day, and returning the bare time would be actively misleading; a warning states which day the result falls on. Negative results wrap backwards correctly, which a plain remainder operator in most languages does not do.

## Methodology

The oracle works in total seconds from midnight using floor division, so a truncating remainder in the engine would show up immediately on the backwards-wrapping cases, of which several are included.
