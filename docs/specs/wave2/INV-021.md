## Purpose

Price a fixed-income bond from its required yield.

## Scope

Plain vanilla bonds with level coupons and whole coupon periods.

## Assumptions

- Clean price.
- Whole coupon periods remaining.

## Inputs

| Name | Label | Type | Default | Units / notes |
|---|---|---|---|---|
| `face_value` | Face value (£) | number | 1000 | - |
| `coupon_rate` | Coupon rate (%) | number | 5 | - |
| `yield_rate` | Required yield (%) | number | 5 | - |
| `years` | Years to maturity | number | 10 | - |
| `coupons_per_year` | Coupons a year | number | 2 | - |

Percentages are entered as human percentages (5 means 5%) and normalised once
inside the engine.

## Validation

Enforced centrally at the engine boundary and by the shared validation module:

- Any non-finite input is rejected with a readable message.
- Any non-finite output is rejected rather than returned, so `NaN` and
  `Infinity` can never reach a user.
- Terms are bounded (maximum 150 years) and monetary amounts capped, so no
  input can spin an amortisation loop indefinitely.


## Formula and logic

Present value of the coupon stream plus the discounted redemption amount.

## Outputs

- `price`
- `total_coupons`
- `current_yield`
- `premium_or_discount`

Formatting is decided by the central registry in
`apps/web/src/components/calculators/outputFormats.ts`, per calculator and per
key, so ratios render as percentages and money as `£1,234.56`.

## Rules and source dependencies

Not rules-sensitive. No statutory values are used.

## Product boundary

Accrued interest between coupon dates, day-count conventions, embedded options and credit risk are NOT modelled.

## Methodology

The oracle discounts every coupon individually rather than using the annuity shortcut.
